# Supabase schema

Tables in the `public` schema of the linked Supabase project (`notes-lab`).
Read from the live database on 2026-11-24.

All IDs are `bigint` identity columns (`GENERATED BY DEFAULT AS IDENTITY`).

## Relationships

```
collections 1 ──< notes >── note_tags ──< tags
           (optional)        (many-to-many)
```

- A note belongs to at most one collection (`notes.collection_id`, optional).
- Notes and tags are many-to-many through `note_tags`.

## Access (row-level security)

RLS is enabled on all four tables. Access needs both a table grant and a policy.

| Table | Grants (`anon`, `authenticated`) | Policies |
|---|---|---|
| `collections` | `SELECT` only | Read: everyone. Insert / update / delete: signed-in users, all rows |
| `notes` | none | none |
| `tags` | none | none |
| `note_tags` | none | none |

## Known issues

- **`notes`, `tags` and `note_tags` are unreachable from the app.** They have no grants and no policies, so every read and write from `anon` or `authenticated` is refused.
- **`collections` is read-only from the app.** Its insert, update and delete policies exist, but the matching grants do not.
- **Rows are not tied to users.** No table has a `user_id`, and the `collections` policies allow any signed-in user to change any row.
- **Leftover names on `collections`.** Its primary key (`notes_pkey`), check constraint (`notes_title_check`) and policies ("… notes") are named after `notes`, which suggests the table was renamed from an earlier `notes` table.
- **The migrations don't match the database.** None of these four tables is created by the files in `supabase/migrations/`. Running the migrations on a fresh database will not reproduce this schema. `npx supabase db pull` can generate a migration that captures the current state.

## Regenerating this document

Read-only queries with the Supabase CLI, for example:

```bash
npx supabase db query --remote --read-only -o table \
  "select table_name, column_name, data_type, is_nullable, column_default
   from information_schema.columns where table_schema = 'public'
   order by table_name, ordinal_position"
```

Also check `pg_constraint` (keys), `pg_policies` (RLS policies) and `has_table_privilege()` (grants).
